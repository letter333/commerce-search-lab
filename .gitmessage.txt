
# 아래 형식을 참고해 이 주석 위에 실제 메시지를 작성한다.
# type(scope): 한국어 요약
#
# 필요한 경우 변경 이유, 달라진 동작, 제약과 검증 근거를 적는다.
#
# Refs #실제이슈번호
#
# type: feat, fix, docs, test, refactor, perf, build, ci, style, chore, revert
# scope: search, query, ranking, api, eval, seeds, build, skills 등 실제 영역.
# 적절한 단일 영역이 없으면 scope와 괄호를 생략한다.
# 한 커밋에는 하나의 검증 가능한 목적과 실제 작업 이슈 하나만 담는다.
# 이슈 종료 키워드는 PR 본문에만 쓰고 커밋에는 Refs를 사용한다.
# 호환성이 깨지면 제목에 !를 붙이고 아래 후터도 함께 작성한다.
# BREAKING CHANGE: 깨지는 계약과 사용자가 수행할 전환 방법
# 비밀값·환경변수 값·자격증명·원본 로그를 메시지에 복사하지 않는다.
# 사용: git commit --cleanup=strip --template .gitmessage.txt
